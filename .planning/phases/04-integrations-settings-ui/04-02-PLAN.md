Append the Notion wizard implementation to `src/integrations-settings.js` (after the existing code from 04-01). The wizard has 5 steps, uses state-first rendering, and calls existing Phase 1 Tauri commands.

**Wizard state:**

```javascript
let notionWizardState = {
  step: 0,             // 0=api-key, 1=share-instruction, 2=db-picker, 3=schema, 4=people-mapping
  integrationId: null,
  databases: [],
  selectedDbId: null,
  selectedDbName: null,
  profile: null,       // Full NotionIntegrationProfile after sync
  mappings: [],        // [{alias, notionUserId, displayName}]
  error: null,
};
```

**Step definitions (5 steps with progress percentages 20/40/60/80/100):**

**Step 0: API Key Entry**
- Title: "Enter Notion API Key"
- Description: "Create an internal integration at notion.so/my-integrations, then paste the API key below."
- Fields: Name input (default "Notion"), API key input (type password, monospace, placeholder "ntn_...")
- Next button: calls `invoke('add_notion_integration', { name, apiKey })`. On success, store `integrationId` in state, advance to step 1. On error, show error message below the form.
- Progress: 20%

**Step 1: Share Instruction (mandatory)**
- Title: "Share Your Database"
- Show a `wizard-info-box` with clear numbered instructions:
  1. Open your Notion database in the browser
  2. Click the "..." menu in the top-right corner
  3. Go to "Connections" (or "Add connections")
  4. Find and add your integration by name
- Description below: "After sharing, click Next to continue."
- Next button: just advances to step 2 (no API call — the DB picker will show the error if sharing wasn't done).
- Progress: 40%

**Step 2: Database Picker**
- Title: "Select Database"
- On entry, show "Loading databases..." text, then call `invoke('list_notion_databases', { integrationId: notionWizardState.integrationId })`.
- On success (array of `{id, name}`): render as `wizard-db-list` with `wizard-db-item` divs. Clicking one selects it (adds `selected` class, stores in state).
- On error or empty list: show the same share instruction text from step 1 in a `wizard-info-box`, plus a "Retry" button that re-fetches. The backend already returns an error message with share instructions when 0 databases are found — display this exact error.
- Next button: disabled until a database is selected. On click, calls `invoke('sync_notion_schema', { integrationId, databaseId, databaseName })`. On success, store `profile` in state, advance to step 3.
- Progress: 60%

**Step 3: Schema Display**
- Title: "Database Schema"
- Render `profile.properties` as a `wizard-schema-table` with columns: Property Name, Type, Options (for select/multi_select types, show comma-separated options; for others show "—").
- Below the table, show `wizard-schema-synced`: "Last synced: {profile.synced_at as localized date/time}"
- Also show a "Re-sync Schema" mini-action-btn that calls `sync_notion_schema` again and re-renders.
- Next button: advances to step 4.
- Progress: 80%

**Step 4: People Mapping**
- Title: "People Mapping"
- Description: "Map aliases (like 'me' or 'team') to Notion workspace users. These aliases can be used in AI output to assign people."
- Pre-populate mapping rows: one row for each `people`-type property found in `profile.properties` (use the property name as a suggested alias). If no people properties, show one empty row.
- Each row: alias text input + Notion user dropdown (populated from `profile.workspace_users` with `{id, name}`) + remove button (x).
- "Add mapping" button adds an empty row.
- State-first pattern: maintain `notionWizardState.mappings` array. On alias input change, update state. On dropdown change, update state (store both `notionUserId` and `displayName`). On remove click, splice from state array and re-render rows.
- Next button label changes to "Finish". On click:
  - Filter out rows where alias is empty or no user selected.
  - Call `invoke('update_notion_people_mappings', { integrationId, mappings })` with the clean array. The `mappings` param format is `[{alias: string, notion_user_id: string, display_name: string}]` (snake_case for Rust deserialization).
  - On success (or if mappings array is empty — skip the call), close wizard and call `loadAllIntegrations()` to refresh Connected section.
  - On error, show error below the mapping rows.
- Progress: 100%

**Cancel behavior:**
- Cancel button visible on all steps.
- On cancel at step 0: just close the modal.
- On cancel at steps 1-4 (integrationId exists): call `invoke('remove_notion_integration', { integrationId })` to clean up the partial profile, then close the modal.
- Always reset `notionWizardState` to initial values when closing.

**openNotionWizard function:**
This is the entry point called by the "Add Notion" button in the Available section (wired in 04-01). It:
1. Resets `notionWizardState` to initial values
2. Sets modal display to 'flex'
3. Calls `renderWizardStep()`

**renderWizardStep function:**
This is the core render function. Based on `notionWizardState.step`:
1. Updates the progress bar width
2. Renders the step content into `#notion-wizard-body`
3. Updates the Next button label ("Next" for steps 0-3, "Finish" for step 4)
4. Attaches step-specific event handlers to newly rendered elements
5. Shows/hides error if `notionWizardState.error` is set

**Important implementation details:**
- All `invoke()` calls should use `window.__TAURI__.core.invoke` (consistent with 04-01 module pattern).
- Use `escapeHtml()` for ALL user-supplied strings rendered via innerHTML (profile names, database names, property names, user names, aliases).
- The Next button handler should disable itself and show "..." text while async operations are in progress to prevent double-clicks.
- The Cancel button handler should be wired once in the `openNotionWizard` function, not re-attached on each render.
- The wizard modal close function should: reset state, set modal display to 'none'.

**Error handling:**
- Step 0 (API key): show error below the API key input in a `wizard-error` div.
- Step 2 (DB picker): show error/share-instructions in the database list area.
- Step 4 (people mapping): show error below the mapping rows.
- All errors: set `notionWizardState.error`, call `renderWizardStep()` to re-render.
