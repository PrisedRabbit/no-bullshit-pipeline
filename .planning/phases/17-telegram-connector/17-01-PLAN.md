Types to define (all derive Serialize, Deserialize, Clone, Debug):
```rust
pub struct TelegramChat {
    pub id: i64,
    pub title: String,     // group/channel title, or first_name for DMs
    pub chat_type: String, // "private", "group", "supergroup", "channel"
}

pub struct TelegramIntegrationProfile {
    pub id: String,         // UUID (our internal ID)
    pub name: String,       // user-given name
    pub chat_id: i64,       // Telegram chat_id to send messages to
    pub chat_title: String, // Display label for the selected chat
    pub chat_type: String,  // "private", "group", "supergroup", "channel"
    pub synced_at: String,  // ISO8601 timestamp of last validation
}
```

Profile I/O (follow linear.rs pattern exactly):
- `save_telegram_profile(profile: &TelegramIntegrationProfile) -> Result<(), String>` — writes to `~/.nbp/integrations/telegram-{id}.json` with 0o600 permissions via `crate::config::get_integrations_dir()`
- `load_telegram_profile(integration_id: &str) -> Result<TelegramIntegrationProfile, String>` — reads from same path, error includes "Sync in Settings > Integrations" hint
- `delete_telegram_profile(integration_id: &str) -> Result<(), String>`

Token helpers (delegate to `super::save_token/get_token/delete_token`):
- `save_telegram_token(integration_id: &str, token: &str) -> Result<(), String>` — uses key `"telegram:{integration_id}"`
- `get_telegram_token(integration_id: &str) -> Result<String, String>`
- `delete_telegram_token(integration_id: &str) -> Result<(), String>`

HTTP helpers using `reqwest::Client` (NO new crate dependencies — reqwest already in Cargo.toml):
- `telegram_get_me(token: &str) -> Result<serde_json::Value, String>` — GET `https://api.telegram.org/bot{token}/getMe`, validate `ok: true` in response, return `result` object. Error: "Invalid Telegram bot token: {detail}"
- `telegram_get_updates(token: &str) -> Result<Vec<TelegramChat>, String>` — GET `https://api.telegram.org/bot{token}/getUpdates?limit=100`, extract unique chats from `result[].message.chat` (and `result[].channel_post.chat`), deduplicate by chat.id, return Vec<TelegramChat>. If result is empty return empty vec (not error).
- `telegram_send_message(token: &str, chat_id: i64, text: &str) -> Result<(), String>` — POST `https://api.telegram.org/bot{token}/sendMessage` with JSON body `{"chat_id": chat_id, "text": text}`, validate `ok: true`. Error: "Failed to send Telegram message: {detail}". Note: Telegram messages have a 4096-char limit; truncate text with "...[truncated]" if needed.

Tauri commands:
```rust
#[tauri::command]
pub async fn add_telegram_integration(name: String, bot_token: String) -> Result<String, String>
```
- Call `telegram_get_me(&bot_token)` — if error, return "Invalid Telegram bot token: {err}"
- Generate UUID id
- Save token via `save_telegram_token(&id, &bot_token)`
- Save initial profile: `TelegramIntegrationProfile { id, name, chat_id: 0, chat_title: String::new(), chat_type: String::new(), synced_at: String::new() }`
- Return id

```rust
#[tauri::command]
pub async fn resolve_telegram_chats(integration_id: String) -> Result<Vec<TelegramChat>, String>
```
- Get token via `get_telegram_token(&integration_id)`
- Call `telegram_get_updates(&token)`
- Return the vec (may be empty — frontend handles empty state with manual entry fallback)

```rust
#[tauri::command]
pub async fn save_telegram_chat(integration_id: String, chat_id: i64, chat_title: String, chat_type: String) -> Result<(), String>
```
- Load existing profile
- Update chat_id, chat_title, chat_type, synced_at = `chrono::Utc::now().to_rfc3339()`
- Save updated profile

```rust
#[tauri::command]
pub async fn remove_telegram_integration(integration_id: String) -> Result<(), String>
```
- Delete token (treat "not found" as success — use same pattern as linear.rs idempotent remove)
- Delete profile (same treatment)
- Collect errors, return combined error if any remain

```rust
#[tauri::command]
pub async fn list_telegram_profiles() -> Result<Vec<TelegramIntegrationProfile>, String>
```
- Scan `get_integrations_dir()` for files matching `telegram-*.json`
- Deserialize each, collect into Vec, return sorted by `name`

Note: No `test_telegram_integration` command needed — validation happens at add time. No schema sync step needed (Telegram has no schema).

Core execute logic:
```rust
pub async fn execute(
    input_path: &Path,
    config: &serde_json::Value,
    output_dir: &Path,
    step_name: &str,
    input_step: &str,
    description: Option<&str>,
) -> Result<PathBuf, String>
```
1. Parse `TelegramConnectorConfig::from_value(config)`
2. Load profile via `crate::integrations::telegram::load_telegram_profile(&connector_config.integration_id)`
3. Validate profile.chat_id != 0 — error: "Telegram integration has no chat configured. Complete setup in Settings > Integrations."
4. Get token via `crate::integrations::telegram::get_telegram_token(&connector_config.integration_id)`
5. Read input file with `fs::read_to_string(input_path)` — strip frontmatter via `crate::connectors::strip_frontmatter(&raw)`, trim
6. Send message via `crate::integrations::telegram::telegram_send_message(&token, profile.chat_id, text)`
7. On success: `fs::create_dir_all(output_dir)`, compute `output_path = output_dir.join(format!("{}.md", step_name))`, call `write_success_output`, return `Ok(output_path)`
8. On failure: write failure output file and return `Err(error_message)`
