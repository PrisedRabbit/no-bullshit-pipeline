  <name>Task 1: Add token budget validation before augmented LLM execution</name>
  <files>src-tauri/src/pipeline_engine.rs, src-tauri/src/connectors/llm.rs</files>
  <action>
In `src-tauri/src/connectors/llm.rs`:
- Change `fn estimate_tokens` to `pub fn estimate_tokens` (make it public for cross-module use)
- Change `fn context_limit_for_provider` to `pub fn context_limit_for_provider` (make it public)
- No other changes to llm.rs

In `src-tauri/src/pipeline_engine.rs`:
- Add a `validate_augmented_prompt_budget()` function that takes the augmented prompt string, and the LLM step config (to extract provider). It:
  1. Parses the provider from the LLM step config using `config.get("provider").and_then(|v| v.as_str()).unwrap_or("openai")`
  2. Calls `connectors::llm::estimate_tokens(&augmented_prompt)` to get token estimate
  3. Calls `connectors::llm::context_limit_for_provider(provider)` to get the context limit
  4. If estimated tokens > context limit, returns `Err` with a clear message: "Augmented prompt ({estimated} est. tokens) exceeds {provider} context limit ({limit} tokens). Your Notion schema may be too large for this model. Try a provider with a larger context window or reduce the number of database properties."
  5. If within budget, returns `Ok(())`

- In the `ConnectorType::Llm` match arm, AFTER `build_augmented_prompt()` succeeds and BEFORE calling `connectors::llm::execute()`:
  - If `augmented` is `Some(ref aug_text)`, call `validate_augmented_prompt_budget(aug_text, &step.config)?`
  - This means if budget validation fails, the step returns Err immediately — no LLM API call, no wasted cost
  - The sidecar file write (already in place) happens before this check, which is fine — the sidecar is for UI display

- Remove the silent truncation behavior from `llm.rs` for the augmented path? NO — keep the existing truncation as a safety net for the non-augmented path and edge cases. The new validation is an explicit pre-flight check that gives a better error message for the augmented case. The truncation in llm.rs remains for backward compatibility on the standard (non-augmented) code path.
  </action>

  <action>
In `src/integrations-settings.js`, in the `renderConnectedIntegrations()` function where Notion cards are built:

1. After computing `syncedAt`, add staleness detection:
   - Parse `profile.synced_at` into a Date object
   - Compare with current time: `const daysSinceSync = Math.floor((Date.now() - new Date(profile.synced_at).getTime()) / (1000 * 60 * 60 * 24))`
   - Define `const isStale = profile.synced_at && daysSinceSync > 7`
   - If no `synced_at` (empty string), treat as stale (`isStale = !profile.synced_at || daysSinceSync > 7`)

2. Update the card detail line to show the staleness warning:
   - Current: `${safeDb} · Synced ${syncedAt}`
   - New: If isStale, append a warning: `${safeDb} · Synced ${syncedAt} · <span class="schema-stale-warning">Schema may be outdated — re-sync recommended</span>`
   - If not stale, keep as is: `${safeDb} · Synced ${syncedAt}`

3. For the "Never synced" case (empty synced_at), show: `${safeDb} · <span class="schema-stale-warning">Never synced — sync schema in wizard</span>`
