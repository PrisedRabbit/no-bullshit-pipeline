<task type="auto">
  <name>Task 1: Implement add_notion_integration and list_notion_databases commands</name>
  <files>
    src-tauri/src/integrations/notion.rs
    src-tauri/src/lib.rs
  </files>
  <action>
    **IMPORTANT: Before writing ANY notion-client code, run `cargo doc -p notion-client --no-deps` and read the generated docs to verify the exact API surface. The research has HIGH confidence on method signatures but MEDIUM confidence on DatabaseProperty variant field access. Adjust code to match actual API.**

    **In `src-tauri/src/integrations/notion.rs`, add these Tauri commands:**

    1. **`add_notion_integration`** — Tauri command accepting `name: String, api_key: String`:
       - Create a `notion_client::endpoints::Client` from the raw token: `Client::new(api_key.clone(), None)`
       - Validate by calling `client.users.retrieve_your_tokens_bot_user().await` — if this fails, return error "Invalid Notion API key: {error}". Do NOT log the actual key.
       - Generate a UUID for the integration ID using `uuid::Uuid::new_v4().to_string()`
       - Save the token: `save_notion_token(&id, &api_key)?`
       - Create an initial (empty) `NotionIntegrationProfile` with the name, empty database fields, empty properties/people/users, and `synced_at` set to empty string
       - Save the profile: `save_notion_profile(&profile)?`
       - Return `Ok(id)` (the generated integration ID as String)

    2. **`list_notion_databases`** — Tauri command accepting `integration_id: String`:
       - Retrieve the token: `get_notion_token(&integration_id)?`
       - Create a client from the token
       - Use `client.search.search_by_title(SearchByTitleRequest { ... })` with:
         - `filter: Some(Filter { property: FilterProperty::Object, value: FilterValue::Database })`
         - `query: None, sort: None, start_cursor: None, page_size: Some(100)`
       - Import types: `notion_client::endpoints::search::title::request::{Filter, FilterProperty, FilterValue, SearchByTitleRequest}`
       - The response contains `results: Vec<PageOrDatabase>`. Extract database entries — each should have an `id` and `title` (check the actual type from cargo doc; may need pattern matching on `PageOrDatabase` enum variants).
       - Define a simple return struct `NotionDatabaseInfo { id: String, name: String }` (derive Serialize)
       - If results are empty, return error: "No databases found. In Notion, open your database, click '...' menu, then 'Connections', and add your integration."
       - Return `Ok(Vec<NotionDatabaseInfo>)` with the list of databases

    3. **Register both commands in `lib.rs` invoke_handler.** Add after the existing Slack integration commands:
       ```
       // Notion integrations
       integrations::notion::add_notion_integration,
       integrations::notion::list_notion_databases,
       ```

    4. Run `cargo check`. If notion-client API differs from research, adjust accordingly. Pay particular attention to:
       - `PageOrDatabase` type in search results — may need to extract database ID/title differently
       - `Client::new` may require `String` not `&str`
       - Error types from notion-client may not implement Display — use `format!("{:?}", e)` if needed
  </action>
  <verify>
    `cargo check` passes. Both commands are registered in invoke_handler. The `add_notion_integration` command validates the token before storing. The `list_notion_databases` command returns database names and IDs with a helpful error when no databases are found.
  </verify>
  <done>
    `add_notion_integration` validates API key via bot user endpoint, stores token via dev-mode-aware helpers, creates initial profile. `list_notion_databases` queries Notion search API filtered to databases and returns id/name pairs. Both registered in invoke_handler.
  </done>

<task type="auto">
  <name>Task 2: Implement sync_notion_schema command</name>
  <files>
    src-tauri/src/integrations/notion.rs
    src-tauri/src/lib.rs
  </files>
  <action>
    **In `src-tauri/src/integrations/notion.rs`, add the sync command:**

    1. **`sync_notion_schema`** — Tauri command accepting `integration_id: String, database_id: String, database_name: String`:
       - Retrieve token and create client
       - Call `client.databases.retrieve_a_database(&database_id).await` to get the `Database` struct
       - Extract `database.properties` (a `HashMap<String, DatabaseProperty>`)
       - Iterate over properties and convert each to `NotionPropertyDef`:
         - For each property, determine the `property_type` string based on the `DatabaseProperty` variant (e.g., `DatabaseProperty::Select { .. }` -> "select")
         - For `Select` and `MultiSelect` variants, extract the `options` field and collect option names into `select_options: Vec<String>`
         - For all other types, set `select_options` to empty vec
         - **CRITICAL:** Check the actual DatabaseProperty enum variants from `cargo doc`. The research says variants are like `DatabaseProperty::Select { name, select, .. }` where `select: SelectPropertyValue` has `options: Vec<OptionValue>`. Verify this. If the actual shape differs, adapt accordingly.
       - Call `client.users.list_all_users(None, Some(100)).await` to get workspace users
         - Handle pagination: if `has_more` is true, loop with `next_cursor` until all users are fetched
         - Convert each `User` to `WorkspaceUser { id: user.id, name: user.name }`
       - Load existing profile: `load_notion_profile(&integration_id)?`
       - Update the profile fields: `database_id`, `database_name`, `properties`, `workspace_users`, `synced_at` (set to `chrono::Utc::now().to_rfc3339()`)
       - Preserve existing `people_mappings` from the loaded profile (do not overwrite — those are set separately)
       - Save the updated profile: `save_notion_profile(&profile)?`
       - Return `Ok(profile)` so the frontend can display the synced schema

    2. **Register in `lib.rs` invoke_handler** (add to the Notion section):
       ```
       integrations::notion::sync_notion_schema,
       ```

    3. Run `cargo check`. The full property type parsing is the most likely place to hit compile errors if DatabaseProperty variants differ from research. Be prepared to iterate.
  </action>
  <verify>
    `cargo check` passes. The `sync_notion_schema` command is registered. The property parsing covers at minimum: Title, RichText, Select, MultiSelect, People, Date. Select/MultiSelect options are extracted into `select_options`.
  </verify>
  <done>
    `sync_notion_schema` retrieves database properties and workspace users, converts them to `NotionPropertyDef` and `WorkspaceUser` types, preserves existing people_mappings, writes synced_at timestamp, and saves the complete profile to disk. Registered in invoke_handler.
  </done>
