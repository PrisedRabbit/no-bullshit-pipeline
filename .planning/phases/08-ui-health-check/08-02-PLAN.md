**`let walkthroughStep = 0;`** — module-local step counter.

**`startWalkthrough()` function:**
- Set `walkthroughStep = 0`
- Get `#walkthrough-overlay`, set `display = 'flex'`
- Call `showWalkthroughStep(0)`

**`showWalkthroughStep(stepIndex)` function:**
- Get step from WALKTHROUGH_STEPS[stepIndex]. If undefined, return.
- Get target element via `document.querySelector(step.selector)`
- Get spotlight (`#walkthrough-spotlight`), card title (`#walkthrough-title`), card desc (`#walkthrough-desc`), step counter (`#walkthrough-step`), prev button (`#walkthrough-prev`), next button (`#walkthrough-next`)
- Set title, desc, step counter text (`(stepIndex + 1) + ' / ' + WALKTHROUGH_STEPS.length`)
- Hide prev button on first step (`stepIndex === 0 ? 'none' : ''`)
- Next button text: `'Done'` on last step, `'Next'` otherwise
- If target exists and has non-zero bounding rect:
  - Use `getBoundingClientRect()` with 8px padding
  - Set spotlight as `position: fixed`, top/left/width/height from rect with padding
  - Use `box-shadow: 0 0 0 9999px rgba(0,0,0,0.6)` for the dark overlay effect
  - Show spotlight (`display = 'block'`)
  - Position walkthrough card below the spotlight (or above if near bottom of viewport). Use `position: fixed`, `left` = spotlight left, `top` = spotlight bottom + 12px. If that would place card below viewport, position above spotlight instead.
- If target not found or has zero dimensions:
  - Hide spotlight (`display = 'none'`)
  - Center the card in viewport instead

**`finishWalkthrough()` async function:**
- Hide `#walkthrough-overlay` (`display = 'none'`)
- Set `appSettings.walkthrough_completed = true`
- Call `await invoke('save_settings', { settings: appSettings })` in try/catch
- Log error to console on failure

**Update `initHealthCheck()` function (from Plan 08-01)** — add these additional listener wires:

- `#walkthrough-prev` click: if `walkthroughStep > 0`, decrement and call `showWalkthroughStep(--walkthroughStep)`
- `#walkthrough-next` click: if last step, call `finishWalkthrough()`. Otherwise increment and call `showWalkthroughStep(++walkthroughStep)`
- `#walkthrough-skip` click: call `finishWalkthrough()`
- `#start-walkthrough-btn` click (Settings button): call `startWalkthrough()`

Do NOT use `element.onclick =` for these — use `addEventListener('click', ...)` since these are wired once in `initHealthCheck()`.

**main.js — Add first-launch walkthrough trigger:**

Modify the `scheduleAudit` function inside the `init().finally()` block (added in Plan 08-01). After `runHealthAudit()` is called, add the first-launch walkthrough trigger:

```javascript
const scheduleAudit = () => {
  if (typeof runHealthAudit === 'function') {
    runHealthAudit();
    // Trigger walkthrough on first launch (after audit so badge is visible)
    // Only if onboarding is already completed (permissions granted)
    if (typeof appSettings !== 'undefined' &&
        appSettings.onboarding_completed &&
        !appSettings.walkthrough_completed &&
        typeof startWalkthrough === 'function') {
      startWalkthrough();
    }
  }
};
```

CRITICAL ordering: walkthrough triggers ONLY if `appSettings.onboarding_completed === true`. If onboarding hasn't been completed, the permissions overlay takes priority. Users who dismiss onboarding will see the walkthrough on their next launch (when onboarding_completed is true but walkthrough_completed is still false).
