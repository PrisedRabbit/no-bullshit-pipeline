<objective>
Add Linear schema prompt augmentation to the pipeline engine so that LLM steps immediately preceding a Linear delivery step automatically receive Linear field format specifications in their prompt.

Purpose: Without augmentation, the LLM has no guidance on valid Linear field values (status names, priority levels, label names, member names). This causes frequent JSON parse failures and field resolution misses. Augmentation provides the LLM with exact valid values from the synced schema.

Output: Updated `pipeline_engine.rs` with `build_linear_augmented_prompt()`, `build_linear_format_spec()`, extended LLM N+1 look-ahead for Linear, and updated Linear retry to use augmented prompt.
</objective>

Add two new functions to `pipeline_engine.rs`, placed after the existing `build_notion_format_spec()` function (around line 244):

**1. `build_linear_format_spec(profile: &LinearIntegrationProfile) -> String`**

Builds a compact format spec string from the Linear integration profile. The spec instructs the LLM to output a single JSON object (not an array — Linear creates one issue per delivery step, unlike Notion which creates multiple pages).

Format spec structure:
```
Output a JSON object with these fields:
Team: {profile.team_name}

- "title" (string, REQUIRED): issue title
- "description" (string): issue description in markdown
- "priority" (string): one of: {profile.priorities mapped to labels, e.g. "No priority, Urgent, High, Medium, Low"}
- "status" (string): one of: {profile.workflow_states mapped to names, e.g. "Backlog, Todo, In Progress, Done, Cancelled"}
- "labels" (array of strings): values from: {profile.labels mapped to names}
- "assignee" (string): one of: {profile.members mapped to display_name (or name as fallback)}

Omit any field you cannot determine from the transcript. Use null for unknown optional fields.
Return ONLY the JSON object. No prose, no markdown, no code fences.
```

Key differences from `build_notion_format_spec()`:
- Output is "a JSON object" (singular), not "a JSON array where each element is an object"
- Fields are fixed (title, description, priority, status, labels, assignee) — not dynamic from schema properties
- Priority uses label strings from `profile.priorities` (e.g., "Urgent", "High")
- Status uses workflow state names from `profile.workflow_states`
- Labels uses label names from `profile.labels` — apply the same MAX_OPTIONS_IN_SPEC=12 cap
- Assignee uses member display_name (or name) from `profile.members` — apply MAX_OPTIONS_IN_SPEC=12 cap
- Workflow states should also apply MAX_OPTIONS_IN_SPEC=12 cap (unlikely to exceed but be safe)

**2. `build_linear_augmented_prompt(step_config, input_path, linear_integration_id) -> Result<String, String>`**

Follow the exact same pattern as `build_augmented_prompt()` (the existing Notion version):
1. Load base prompt from `prompt_template` or `prompt_inline` in step_config (identical logic)
2. Substitute transcript content via `substitute_variables` (identical logic)
3. Load Linear integration profile via `crate::integrations::linear::load_linear_profile(linear_integration_id)` — hard fail with actionable message if profile not found
4. Verify profile has synced schema: check `profile.workflow_states.is_empty() && profile.team_id.is_empty()` — hard fail with "Sync schema in Settings" message if empty
5. Build format spec via `build_linear_format_spec(&profile)`
6. Append format spec to base prompt: `format!("{}\n\n{}", base_prompt, format_spec)`

Error messages should reference "Linear" (not "Notion") and mention the correct Settings path.
