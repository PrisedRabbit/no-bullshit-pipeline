  <action>
Create `src-tauri/src/integrations/linear.rs` following the Notion integration pattern in `integrations/notion.rs`.

**Types** (all derive Serialize, Deserialize, Clone, Debug):

1. `LinearIntegrationProfile` — the main profile struct, stored as `~/.nbp/integrations/linear-{id}.json`:
   - `id: String` (UUID)
   - `name: String` (user-provided display name)
   - `team_id: String` (selected Linear team ID)
   - `team_name: String`
   - `workflow_states: Vec<LinearWorkflowState>` — status options (Backlog, Todo, In Progress, Done, Cancelled)
   - `labels: Vec<LinearLabel>` — issue labels
   - `members: Vec<LinearMember>` — team members
   - `priorities: Vec<LinearPriority>` — priority levels (static: 0=No priority, 1=Urgent, 2=High, 3=Medium, 4=Low)
   - `synced_at: String` (RFC3339 timestamp)

2. `LinearWorkflowState` — `{ id: String, name: String, type_name: String }` (type_name is one of: backlog, unstarted, started, completed, cancelled)

3. `LinearLabel` — `{ id: String, name: String, color: String }`

4. `LinearMember` — `{ id: String, name: String, display_name: String, email: Option<String> }`

5. `LinearPriority` — `{ priority: i32, label: String }` (static list: 0=No priority, 1=Urgent, 2=High, 3=Medium, 4=Low)

6. `LinearTeamInfo` — `{ id: String, name: String }` (for list_linear_teams return)

**Credential helper wrappers** (delegate to shared helpers in mod.rs — same pattern as Notion):
- `save_linear_token(integration_id, token)` → `super::save_token(&format!("linear:{}", integration_id), token)`
- `get_linear_token(integration_id)` → `super::get_token(&format!("linear:{}", integration_id))`
- `delete_linear_token(integration_id)` → `super::delete_token(&format!("linear:{}", integration_id))`

**Profile I/O** (same pattern as Notion):
- `save_linear_profile(profile)` — write to `~/.nbp/integrations/linear-{id}.json` with 0o600 permissions
- `load_linear_profile(integration_id)` — read and deserialize
- `delete_linear_profile(integration_id)` — remove file

**Internal GraphQL helper**:
- `graphql_request(token: &str, query: &str, variables: Option<serde_json::Value>) -> Result<serde_json::Value, String>`
  - POST to `https://api.linear.app/graphql`
  - Headers: `Content-Type: application/json`, `Authorization: {token}` (no "Bearer" prefix — Linear API keys use raw token)
  - Body: `{"query": query, "variables": variables}`
  - Parse response JSON, check for `errors` array, return `data` field
  - Use `reqwest::Client::new()` (reqwest is already a dependency)

**Tauri commands**:

1. `add_linear_integration(name: String, api_key: String) -> Result<String, String>`:
   - Validate by calling GraphQL: `query { viewer { id name email } }`
   - If query fails → return error "Invalid Linear API key: {details}"
   - Generate UUID for integration ID
   - Store token via `save_linear_token(&id, &api_key)`
   - Create initial empty profile (no team selected, empty schema)
   - Save profile to disk
   - Return the integration ID

2. `test_linear_integration(integration_id: String) -> Result<String, String>`:
   - Load token via `get_linear_token`
   - Call GraphQL viewer query
   - Return "Connected" on success, descriptive error on failure

3. `remove_linear_integration(integration_id: String) -> Result<(), String>`:
   - Delete token (treat "not found" as success — idempotent, same as Notion)
   - Delete profile file (treat "not found" as success)
   - Collect real errors, return joined if any

Add `pub mod linear;` to `src-tauri/src/integrations/mod.rs` after the existing `pub mod save_path;` line.

**Do NOT use a third-party Linear SDK crate.** Use reqwest (already in Cargo.toml) with raw GraphQL queries. This avoids adding a new dependency and gives full control over the query structure. The Notion connector uses notion-client crate, but Linear's GraphQL API is simple enough for direct reqwest calls.

**Tauri commands to add:**

4. `list_linear_teams(integration_id: String) -> Result<Vec<LinearTeamInfo>, String>`:
   - Load token via `get_linear_token`
   - GraphQL query: `query { teams { nodes { id name } } }`
   - Parse `data.teams.nodes` array into `Vec<LinearTeamInfo>`
   - Return error if no teams found (shouldn't happen — every Linear workspace has at least one team)

5. `sync_linear_schema(integration_id: String, team_id: String, team_name: String) -> Result<LinearIntegrationProfile, String>`:
   - Load token
   - **Fetch workflow states for team**: `query($teamId: String!) { team(id: $teamId) { states { nodes { id name type } } } }`
     - Map to `Vec<LinearWorkflowState>` where `type_name` comes from the `type` field
   - **Fetch labels for team**: `query($teamId: String!) { team(id: $teamId) { labels { nodes { id name color } } } }`
     - Map to `Vec<LinearLabel>`
   - **Fetch members for team**: `query($teamId: String!) { team(id: $teamId) { members { nodes { id name displayName email } } } }`
     - Map to `Vec<LinearMember>` — use `displayName` for `display_name`, `name` for `name`
   - **Priorities are static** — do not fetch, hardcode:
     ```
     vec![
       LinearPriority { priority: 0, label: "No priority".into() },
       LinearPriority { priority: 1, label: "Urgent".into() },
       LinearPriority { priority: 2, label: "High".into() },
       LinearPriority { priority: 3, label: "Medium".into() },
       LinearPriority { priority: 4, label: "Low".into() },
     ]
     ```
   - Load existing profile to preserve `name` field (user-supplied display name)
   - Build updated `LinearIntegrationProfile` with new team_id, team_name, all schema fields, `synced_at = Utc::now().to_rfc3339()`
   - Save profile to disk
   - Return the updated profile

   NOTE: Use 3 separate GraphQL queries (states, labels, members) rather than one combined query. This keeps each query simple and error messages specific. The overhead of 3 HTTP calls is negligible for a setup wizard that runs once.

6. `list_linear_profiles() -> Result<Vec<LinearIntegrationProfile>, String>`:
   - Scan `~/.nbp/integrations/` for files matching `linear-*.json`
   - Parse and return all profiles (same pattern as `list_notion_profiles`)
