**1. Extend StepStatus struct** in src-tauri/src/pipelines.rs (line ~78):

Add two new optional fields after the existing `error` field:

```rust
#[serde(skip_serializing_if = "Option::is_none")]
pub duration_secs: Option<f64>,
#[serde(skip_serializing_if = "Option::is_none")]
pub augmented_prompt: Option<String>,
```

`duration_secs` is computed from `completed_at - created_at` (both RFC3339 timestamps already in step .md frontmatter). `augmented_prompt` is the full augmented prompt text when prompt augmentation was used for this step.

**2. Extend parse_step_status()** in src-tauri/src/pipeline_engine.rs (line ~918):

Change the return type from `(String, Option<String>)` to `(String, Option<String>, Option<f64>, Option<String>)` — adding duration_secs and augmented_prompt.

Inside the frontmatter parsing loop, also extract:
- `created_at:` → store in a local `let mut created_at: Option<String> = None;`
- `completed_at:` → store in a local `let mut completed_at: Option<String> = None;`
- `augmented_prompt:` → store in a local `let mut augmented_prompt: Option<String> = None;`. The value is a quoted string that may be very long — extract the value after `augmented_prompt:` trimmed.

After the loop, compute duration_secs:
```rust
let duration_secs = match (&created_at, &completed_at) {
    (Some(c), Some(d)) => {
        let start = chrono::DateTime::parse_from_rfc3339(c).ok();
        let end = chrono::DateTime::parse_from_rfc3339(d).ok();
        match (start, end) {
            (Some(s), Some(e)) => {
                let dur = e.signed_duration_since(s);
                Some(dur.num_milliseconds() as f64 / 1000.0)
            }
            _ => None,
        }
    }
    _ => None,
};
```

Return `(status, error, duration_secs, augmented_prompt)`.

Then in parse_step_status(), we won't look for augmented_prompt in frontmatter. Instead, update get_step_outputs() to check for the `.augmented-prompt.txt` sidecar file:


This avoids modifying every connector's frontmatter format. The augmented_prompt field comes from the sidecar file in get_step_outputs(), not from parse_step_status(). Revert the parse_step_status changes for augmented_prompt — keep it as `(String, Option<String>, Option<f64>)` (3-tuple: status, error, duration_secs).
