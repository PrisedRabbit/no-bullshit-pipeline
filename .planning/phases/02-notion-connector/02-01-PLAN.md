  <name>Task 1: Create connectors/notion.rs with helper functions and execute() entry point</name>
  <files>src-tauri/src/connectors/notion.rs, src-tauri/src/connectors/mod.rs</files>
  <action>
Create `src-tauri/src/connectors/notion.rs` with the following functions. Follow the exact `execute()` signature from `connectors/slack.rs`.

**1. NotionConnectorConfig struct and from_value():**
- Parse `integration_id` from `serde_json::Value` config
- Return descriptive error if missing

**2. extract_json_array(content: &str) -> Result<Vec<serde_json::Value>, String>:**
- Call `crate::connectors::strip_frontmatter(content)` first
- Try direct `serde_json::from_str` on trimmed body
- Try extracting from ` ```json ... ``` ` code fence (find "```json", skip 7 chars, find closing "```")
- Try extracting from bare ` ``` ... ``` ` fence (find "```\n", skip 4 chars, find closing "```")
- On failure: return error showing first 500 chars of raw content: `"Notion connector: could not parse LLM output as JSON array.\nExpected a JSON array like: [{\"Title\": \"...\", ...}]\nGot: {preview}"`
- This is the hard-fail decision from pre-roadmap: no silent fallthrough

**3. resolve_select_value(value: &str, property_name: &str, profile: &NotionIntegrationProfile) -> String:**
- Find property in `profile.properties` by name
- If not found or `select_options` is empty, return value unchanged (passthrough for Status properties with empty options — known Phase 1 limitation)
- Case-insensitive search: `opt.eq_ignore_ascii_case(value)`
- If match found, return the canonical (profile) casing
- If no match, return value unchanged (let Notion API reject if truly invalid — better than silently dropping)

**4. resolve_people_aliases(aliases: &[serde_json::Value], profile: &NotionIntegrationProfile) -> Vec<User>:**
- For each alias value, get string with `as_str()`
- Find matching `PeopleMapping` in `profile.people_mappings` via case-insensitive alias match
- Construct `User` struct with `id` field from mapping's `notion_user_id`
- For `User` construction: try `..Default::default()` first. If `User` does not implement `Default` (check via compile), construct all fields explicitly: `id`, `name: Some(mapping.display_name.clone())`, `avator_url: None`, `user_type: None` (note the crate's typo "avator")
- Skip aliases that don't match any mapping (filter_map pattern)
- Return collected Vec<User>

**5. build_notion_properties(item: &serde_json::Value, profile: &NotionIntegrationProfile) -> Result<BTreeMap<String, PageProperty>, String>:**
- Iterate `profile.properties` (not the JSON keys) to drive property mapping — this ensures only known schema properties are sent
- For each property, look up the key in the JSON `item` object
- Skip if missing or null
- Match on `prop_def.property_type.as_str()`:
  - `"title"` → `PageProperty::Title { id: None, title: vec![RichText::Text { text: Text { content, link: None }, annotations: None, plain_text: None, href: None }] }`
  - `"rich_text"` → `PageProperty::RichText { id: None, rich_text: vec![RichText::Text { ... }] }`
  - `"select"` → call `resolve_select_value()`, then `PageProperty::Select { id: None, select: Some(SelectPropertyValue { id: None, name: Some(canonical), color: None }) }`
  - `"multi_select"` → normalize to array (handle string input as single-element array), resolve each value, `PageProperty::MultiSelect { id: None, multi_select: Vec<SelectPropertyValue> }`
  - `"people"` → normalize to array (handle string as single-element), call `resolve_people_aliases()`, skip if result is empty (do NOT send empty people array), `PageProperty::People { id: None, people: users }`
  - `"date"` → `PageProperty::Date { id: None, date: Some(DatePropertyValue { start: Some(DateOrDateTime::Date(date_str.to_string())), end: None, time_zone: None }) }` — NOTE: DateOrDateTime variant name needs cargo doc verification; if compile fails try `DateOrDateTime::DateTime` or construct via string
  - `"number"` → use `value.as_f64()`, construct `PageProperty::Number { id: None, number: Some(...) }` — the Number type needs cargo doc verification; try `serde_json::Number::from_f64()` or direct f64
  - `"checkbox"` → `PageProperty::Checkbox { id: None, checkbox: value.as_bool().unwrap_or(false) }`
  - `"url"` → `PageProperty::Url { id: None, url: value.as_str().map(String::from) }`
  - `"email"` → `PageProperty::Email { id: None, email: value.as_str().map(String::from) }`
  - `"phone_number"` → `PageProperty::PhoneNumber { id: None, phone_number: value.as_str().map(String::from) }`
  - `"status"` → same as select (uses `resolve_select_value()` which passes through when options empty), `PageProperty::Status { id: None, status: Some(SelectPropertyValue { ... }) }`
  - Computed/read-only types (`"formula"`, `"rollup"`, `"relation"`, `"created_time"`, `"last_edited_time"`, `"created_by"`, `"last_edited_by"`, `"unique_id"`, `"unknown"`) → `continue` (skip)
- After loop: if `properties.is_empty()`, return error: "No properties could be mapped from LLM output to Notion schema"

**6. pub async fn execute(input_path, config, output_dir, step_name, input_step, description) -> Result<PathBuf, String>:**
- Parse config via `NotionConnectorConfig::from_value(config)`
- Load profile via `crate::integrations::notion::load_notion_profile(&connector_config.integration_id)`
- Get token via `crate::integrations::notion::get_notion_token(&connector_config.integration_id)`
- Create client: `Client::new(token, None)`
- Read input file content
- Call `extract_json_array(&raw)` — hard fail on parse error
- For each item in the JSON array:
  - Call `build_notion_properties(item, &profile)`
  - Build `CreateAPageRequest { parent: Parent::DatabaseId { database_id: profile.database_id.clone() }, icon: None, cover: None, properties, children: None }`
  - Call `client.pages.create_a_page(request).await` — map error with `format!("Failed to create Notion page: {:?}", e)`
  - Collect page ID (or URL if `page.url` field exists) into results vec
- Write output markdown to `{output_dir}/{step_name}.md` with YAML frontmatter matching slack.rs pattern (status: done, connector: notion, integration_id, page count, page IDs)
- Create output_dir via `fs::create_dir_all` before writing

- `Page` return type — use `page.id` for output; if `page.url` exists, prefer it.

These are all compile-time discoveries. If cargo is unavailable, use the most likely variant from research and note the assumption.
